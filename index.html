AWS Cloud Networking Project

VPC Peering Architecture

A hands-on AWS project demonstrating secure private communication between two Virtual Private Clouds using VPC Peering, route tables, security groups, and a bastion host.

GitHub Repository Explore Architecture

01 / Network Architecture

VPC A

10.10.0.0/16

  • Public subnet: 10.10.1.0/24
  • Private subnet: 10.10.2.0/24
  • Bastion host for SSH administration
  • App-A: 10.10.2.10

VPC B

10.20.0.0/16

  • Private subnet: 10.20.1.0/24
  • App-B: 10.20.1.10
  • No public IPv4 on App-B
  • Private routes to VPC A

Connection: An active VPC Peering connection links both VPCs. Route tables direct traffic to the remote VPC through the peering connection.

02 / Technologies Used

Amazon VPC · VPC Peering · Amazon EC2 · Route Tables · Internet Gateway · Security Groups · AWS IAM · Linux · SSH

03 / Implementation

  1. Created two VPCs with non-overlapping CIDR ranges.
  2. Configured public and private subnets.
  3. Created and activated the VPC Peering connection.
  4. Configured route tables and security-group rules.
  5. Launched a bastion host and two private EC2 instances.
  6. Connected to both private instances through SSH.
  7. Validated communication between the private instances in both directions.

04 / Testing & Results

✓ App-A → App-B: Ping successful

✓ App-B → App-A: Ping successful

✓ SSH from bastion to both private instances: Successful

These results confirm private connectivity through the configured peering routes and security-group rules at the time of testing.

05 / Security Practices

  • Application instances have no public IPv4 addresses.
  • Bastion SSH access is restricted to a specific client IP.
  • Security groups permit only the required test and administrative traffic.
  • No private keys or AWS credentials are published on this page.

06 / Key Learnings

Practical experience with cloud network design, subnetting, route propagation concepts, private EC2 access, SSH agent forwarding, security-group troubleshooting, and end-to-end connectivity validation.
